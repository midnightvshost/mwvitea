Listă de verificare pentru viteza site-ului și Core Web Vitals

Paginile rapide sunt mai ușor de folosit și mai ușor de clasat. Folosește această listă pentru a găsi părțile lente ale site-ului, a rezolva cele mai mari cauze și a menține performanța după lansare.

Actualizat în noiembrie 202612 min de cititPDF

1. Măsoară paginile care contează

Începe cu șabloanele care aduc trafic și venituri: pagina principală, produs, categorie, serviciu și finalizarea comenzii. Un scor perfect pe o pagină pe care nu o vizitează nimeni nu este util.

  • Folosește date de teren din Chrome UX Report sau din platforma de analiză pentru a vedea performanța reală pe mobil.
  • Folosește un instrument de laborator precum PageSpeed Insights sau Lighthouse pentru a găsi cauzele concrete.
  • Testează aceeași pagină de mai multe ori; scripturile terțe și cache-ul pot schimba rezultatele.
  • Compară separat mobilul și desktopul și notează data fiecărui test.
  • Stabilește o valoare de referință pentru LCP, INP și CLS înainte de a schimba codul.

2. Repară imaginile și Largest Contentful Paint

Imaginile sunt adesea cea mai grea parte a paginii și elementul care determină LCP. Rezolvă-le înainte de a rescrie codul aplicației.

  • Comprimă fotografiile și folosește AVIF sau WebP, cu fallback unde este nevoie.
  • Setează atributele width și height pentru ca browserul să rezerve spațiu.
  • Servește dimensiunea potrivită pentru fiecare ecran, nu o singură imagine originală uriașă.
  • Nu aplica lazy-load imaginii principale sau imaginii de produs; încarcă-le devreme.
  • Folosește un CDN sau un serviciu de imagini care redimensionează și convertește automat.

3. Reduce JavaScript și scripturile terțe

Fiecare tag are un cost. Analiza, widgeturile de chat, instrumentele de consimțământ, fonturile și scripturile de testare concurează pe același fir principal.

  • Inventariază fiecare script terț și elimină-l pe cel pe care nu îl folosește nimeni.
  • Încarcă scripturile necritice după ce pagina devine interactivă sau doar când este nevoie.
  • Împarte bundle-urile mari și elimină bibliotecile nefolosite.
  • Verifică managerul de taguri ca un singur container să nu încarce zeci de taguri pe fiecare pagină.
  • Testează pagina cu limitarea CPU pentru mobil lent, nu doar pe un laptop rapid.

4. Fonturi, CSS și stabilitatea layoutului

Textul trebuie să apară rapid și să rămână pe loc. Schimbarea fonturilor, CSS-ul întârziat și reclamele pot provoca mișcări vizibile.

  • Preîncarcă fișierele principale de font și folosește font-display: swap.
  • Subsetează fonturile și elimină greutățile sau limbile pe care nu le folosești.
  • Include CSS-ul critic inline și amână restul acolo unde este practic.
  • Rezervă spațiu pentru reclame, embed-uri, bannere și notificări de cookie-uri.
  • Evită fonturile-iconi când un set mic de SVG este suficient.

5. Găzduire, cache și TTFB

Un front end rapid nu poate repara un server lent. Verifică timpul până la primul byte și cât de des pot refolosi vizitatorii fișierele din cache.

  • Măsoară TTFB din regiunile în care se află clienții tăi.
  • Activează compresia și un CDN pentru fișierele statice.
  • Cache-uiește HTML doar dacă ai o modalitate sigură de a-l invalida.
  • Revizuiește periodic software-ul serverului, pluginurile și interogările bazei de date.
  • Ferește-te de apelurile API lente și de lanțurile de redirecționare înainte ca pagina să se afișeze.

6. Testează pe dispozitive reale și monitorizează după lansare

Performanța nu este un scor obținut o singură dată. Imaginile, scripturile și funcțiile noi o vor schimba dacă nimeni nu urmărește cifra.

  • Testează pe un telefon de gamă medie și pe o conexiune lentă.
  • Verifică șabloanele principale într-o fereastră privată, cu cache curat.
  • Stabilește un buget de performanță pentru greutatea paginii și Core Web Vitals.
  • Monitorizează datele de teren și alertă la regresii după lansări.
  • Revizuiește lunar cele mai lente pagini și rezolvă mai întâi cauza principală.
Începe cu șablonul cel mai important: îmbunătățirea unei pagini de produs sau serviciu bate de obicei lustruirea paginii principale.
